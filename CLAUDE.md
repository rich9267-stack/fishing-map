## Rules
- Code is split (UX step 2): `index.html` = HTML only (~54 KB), `css/app.css`, `js/01…13-*.js` + `js/99-boot.js` (plain scripts sharing one scope, loaded in order), `sw.js` (offline cache). Libraries load from CDN. NEVER read a whole js file; find the part with `grep -n "// ---- " js/*.js`, then Read only that range.
- Startup calls (`load()`, `gate()`…) live in `js/99-boot.js` because functions are NOT hoisted across files. A new top-level statement that starts async work and calls a function from a later file goes in 99-boot.js too. New feature = add to the file whose topic fits (map below), or a new `js/NN-name.js` + its `<script>` tag in index.html + `APP_FILES` in sw.js.
- Database changes: apply as a Supabase migration, then save the SQL as the next `setup/NN-name.sql`. Test rules with pretend users inside `begin; … rollback;`.
- Deploy: `git push` to main → GitHub Pages. Check `gh run list --limit 1` says success before telling Richard.
- Shipping: run `sh bump.sh` (bumps the `sw.js` cache name AND the `?v=` on every css/js tag in index.html — both must change together).
- Checks: `cd tests && npm install` (first time), then `sh run-all.sh` (needs ALL OK). Copy the newest `tests/test34.js` as a template for a new one; it fakes Supabase and the web APIs; `tests/load.js` stitches index.html + css/js back together for jsdom. Exit code 0 = no crash; read the printed lines for correctness (to prove a refactor changed nothing, diff the printed output before and after, ignoring clock times).
- Don't commit until Richard says so. Git commit trailers: see the session reminder.
- When you ship something people can see, add an entry at the top of `WHATS_NEW` (`✨ What's new` in index.html).
- Keep this file and README.md short. New step details → `docs/build_history.md`; only update the one-line status in README and the plan doc.
